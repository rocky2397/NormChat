# Table extraction — 2026-08-12

Q6 asks for the minimum concrete cover `c_min,dur` in exposure class XC4.
Before this change the tool answered **15 mm**, having read across the
**S1** row of `Tabelle 4.4N` while the question concerned S4. Plain text
extraction returns cells in reading order, so row membership survives only
as sequence, and a flattened grid is legible enough to be misread — prose
failures announce themselves, this one produced a plausible number.

Tables are now detected with `page.find_tables()` (present in the installed
PyMuPDF and previously unused), gated on a `Tabelle N` caption, serialised
to Markdown and emitted as their own chunks. The caption gate is what makes
detection usable: on `ÖNORM EN 1992-1-1` it reports 87 pages while only 32
carry a caption, the remainder being multi-column prose read as grids.
Recall against captioned pages is 31/32.

## Result — Q6 goes from level 1 to level 7

| | before | after |
| --- | --- | --- |
| EN value | 15 mm, S1 row | **30 mm, S4, Tabelle 4.4N, p. 56** |
| Austrian value | "Tabelle 3", believed invented | **25 mm, Tabelle 3, p. 13** |

Both values are now correct, attributed to a real table and page, and the
answer explains the deviation: Austria groups `XC2/XC3/XC4` into one column
where the EN separates `XC4`.

## Stacked headers were the decisive part

The first attempt still answered 25 mm for the *EN* table — the `XC2/XC3`
column. Norm tables stack a merged title and a spanning group label above
the real column names:

```
row 0:  Dauerhaftigkeitsanforderung für cmin,dur (mm)   (7 empty cells)
row 1:  Anforderungsklasse | Expositionsklasse nach Tabelle 4.1 | …
row 2:           | X0 | XC1 | XC2/XC3 | XC4 | XD1/XS1 | …
row 3:  S1 | 10 | 10 | 10 | 15 | 20 | …
```

Markdown convention says row 0 is the header, so serialising naively put
the exposure classes in what reads as a data row and the model miscounted
columns. The header is now taken as the most populated of the leading rows,
with empty header cells filled from the spanning rows above — so the first
column is labelled `Anforderungsklasse` rather than left blank.

## No regression on Q1–Q5

Retrieval is identical with and without tables: 5/12 at `reranked` and
`final` in both. Table chunks do enter the context — 4 of 13 sources for
Q3, 2 of 13 for Q5 — and both answers still hold: Q3 cites §6.2.3 with the
truss model, Q5 contrasts 1,0 against 0,85 and reaches the Austrian annex.

Corpus grew from 9,579 to 10,503 chunks; 924 tables across 39 documents,
zero ingestion failures.

## Two corrections to earlier findings

**There was no fabrication.** The run note of 2026-08-11 recorded that Q6
cited a `Tabelle 3` in `ÖNORM B 1992-1-1` that "does not exist in the
document", and called it the only fabrication observed in any run. It does
exist, on p. 13, and 25 mm is the correct Austrian value. The earlier check
grepped the flattened page text, and that caption sits inside a table
region — the diagnostic used to declare it invented was blind to the thing
it was looking for.

**The probe cannot see this improvement.** Gold labels are
`(norm_reference, page)`, so a prose chunk and a table chunk from the same
page score identically. Recall is flat across this change while the answer
went from wrong to right. The harness validates that the right *page*
arrives; nothing measures whether its content is legible once it does. Only
the Q6 answer evidences this work, which is a gap in the eval design rather
than in the change.

## Not done

The flattened copy still exists alongside the serialised one — excluding
table regions would mean rewriting `extract_page_text()`, which deliberately
reproduces `get_text()` byte-for-byte because boilerplate detection depends
on that layout. The duplication is measurably harmless so far.

Images remain unread: 2,189 across the corpus, of which roughly 44% are
figure-sized. Q4's answers already cite `Bild 6.26` and `Bild 6.27` without
being able to read them.
